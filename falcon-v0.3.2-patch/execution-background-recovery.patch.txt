Forex Falcon Bridge v1.8 MTG/Recovery SAME-PAIR + post-loss wait patch
=====================================================================

Base: execution_background.js from Falcon Bridge Lite FINAL v1.7.

USER-LOCKED BEHAVIOR
--------------------
1) After any confirmed LOSS, do NOT switch pair.
2) Stay on the same pair for the next MTG / Recovery step.
3) Wait one full selected timeframe after the confirmed LOSS before allowing the next trade.
   - 10s TF -> wait 10 seconds
   - 15s TF -> wait 15 seconds
   - 30s TF -> wait 30 seconds
   - 60s TF -> wait 60 seconds
   - 120s TF -> wait 120 seconds
   - 300s TF -> wait 300 seconds
4) Main MTG still progresses only after confirmed broker LOSS.
5) After the final Main MTG loss, Recovery starts automatically and remains on the same pair.
6) One-trade-at-a-time lock remains unchanged.

PATCH A — preserve configured recovery MTG step count
-----------------------------------------------------
REPLACE:
state.settings.recoveryProfitTarget=Number(state.settings.recoveryProfitTarget??2);state.settings.recoveryMtgSteps=4;

WITH:
state.settings.recoveryProfitTarget=Number(state.settings.recoveryProfitTarget??2);
state.settings.recoveryMtgSteps=Math.max(1,Math.min(20,Number(state.settings.recoveryMtgSteps??4)));

PATCH B — add timeframe-based post-loss cooldown helper
-------------------------------------------------------
Immediately after:
const SIGNAL_GAP_MS=0;

ADD:
const lossCooldownMs=(expirySeconds)=>{
 const e=Math.max(1,Number(expirySeconds)||30);
 return e*1000;
};

PATCH C — block dispatch during post-loss wait
-----------------------------------------------
In dispatch(), immediately after the normal profit-pause check, ADD:
if(now<Number(state.recoveryCooldownUntil||0)){
 const waitMs=Number(state.recoveryCooldownUntil||0)-now;
 block('post_loss_wait',`Waiting ${Math.ceil(waitMs/1000)}s after previous loss before next trade on ${state.cycle?.pair||signal.pair}.`,signal);
 return;
}

This makes 30s trades wait 30 seconds after a confirmed loss before the next MTG/Recovery trade can be sent.

PATCH D — disable pair switching after losses
---------------------------------------------
If this block exists in dispatch():
if(state.cycle?.allowPairSwitch){ ... change pair ... }

REPLACE THE WHOLE BLOCK WITH:
if(state.cycle?.allowPairSwitch){
 state.cycle={...state.cycle,allowPairSwitch:false,switchFromPair:null};
}

PATCH E — Main MTG LOSS handling: SAME pair + wait
--------------------------------------------------
Inside handleResult(), in the normal MAIN loss path, use this logic:

const lossTotal=Number(((cycle.lossTotal||0)+Math.abs(profit)).toFixed(2));
const nextStep=cycle.step+1;

if(nextStep>=cycle.amounts.length){
 const target=Number(state.settings.recoveryProfitTarget??2);
 state.recovery={
  active:true,
  remaining:Number((lossTotal+target).toFixed(2)),
  targetProfit:target,
  cycleNumber:(state.recovery?.cycleNumber||0)+1,
  step:0,
  lastStake:null,
  lastPayout:null
 };
 state.cycle={
  market:t.market,
  pair:t.pair,
  expirySeconds:t.expirySeconds,
  direction:t.direction,
  step:0,
  amounts:state.settings.mtgAmounts.slice(),
  mode:state.settings.mtgMode,
  recoveryMode:true,
  allowPairSwitch:false,
  switchFromPair:null
 };
 state.recoveryCooldownUntil=Date.now()+lossCooldownMs(t.expirySeconds);
 log('warn',`Full MTG ladder lost • Recovery started on SAME pair ${t.pair} • wait ${t.expirySeconds}s before next trade • $${state.recovery.remaining.toFixed(2)} remaining`);
}else{
 state.cycle={...cycle,step:nextStep,lossTotal,allowPairSwitch:false,switchFromPair:null};
 state.recoveryCooldownUntil=Date.now()+lossCooldownMs(t.expirySeconds);
 log('warn',`MAIN LOSS • stay on ${t.pair} • wait ${t.expirySeconds}s before MTG${nextStep}`);
}

PATCH F — Recovery LOSS handling: SAME pair + wait
--------------------------------------------------
In the recovery loss path, after incrementing the recovery step, DO NOT set allowPairSwitch=true.
Use:

const nextStep=(state.cycle?.step||0)+1;
state.recovery.step=nextStep;
state.cycle={...(state.cycle||{}),step:nextStep,recoveryMode:true,amounts:state.settings.mtgAmounts.slice(),mode:state.settings.mtgMode,allowPairSwitch:false,switchFromPair:null};
state.recoveryCooldownUntil=Date.now()+lossCooldownMs(t.expirySeconds);

if(nextStep>Number(state.settings.recoveryMtgSteps??4)){
 state.recovery.cycleNumber=(state.recovery.cycleNumber||1)+1;
 state.recovery.step=0;
 state.cycle={...state.cycle,step:0,allowPairSwitch:false,switchFromPair:null};
 log('warn',`Recovery ladder lost • staying on ${t.pair} • wait ${t.expirySeconds}s before next recovery cycle • remaining $${state.recovery.remaining.toFixed(2)}`);
}else{
 log('warn',`Recovery loss • staying on ${t.pair} • wait ${t.expirySeconds}s before next recovery trade • remaining $${state.recovery.remaining.toFixed(2)}`);
}

PATCH H — Recovery anti-stall eligibility
-----------------------------------------
Keep Recovery from being rejected by an exhausted Main-cycle eligibility lock, but DO NOT change pair.

In dispatch():
const eligibilityCycle=(recovery||state.recovery?.active===true)?null:state.cycle;
if(!C.eligible(signal,state.settings,now,state.enabledAt,eligibilityCycle)){
 block('signal_not_eligible','Signal failed route, confidence, or timing eligibility.',signal);
 return;
}

In acceptLocalSignal():
const recoveryCandidate=state.recovery?.active===true;
const eligibilityCycle=recoveryCandidate?null:state.cycle;
if(!C.eligible(s,state.settings,now,state.enabledAt,eligibilityCycle)){
 desktopEvent(`BLOCKED · eligibility · ${s.pair} ${s.expirySeconds}s ${s.confidence.toFixed(1)}%`,{stage:'BLOCKED'});
 return;
}
await dispatch(s,recoveryCandidate);

IMPORTANT: during Recovery, only accept a signal whose pair matches state.cycle.pair / the pair that just lost. This preserves SAME-PAIR Recovery while removing the exhausted-main-cycle stall.

PATCH I — same-pair guard before dispatch
-----------------------------------------
Before dispatching an MTG/Recovery candidate, add:
const lockedPair=C.pair(state.cycle?.pair||'');
if(state.cycle&&lockedPair&&C.pair(signal.pair)!==lockedPair){
 block('mtg_pair_locked',`MTG/Recovery locked to ${lockedPair}; ignoring ${signal.pair}.`,signal);
 return;
}

This is the final protection that prevents automatic pair selection from changing pair during an active MTG or Recovery sequence.
