# Forex Falcon — Next Candle Intelligence

Mobile-first fixed-horizon market analysis dashboard.

## Locked UI rules
- Pairs: EURUSD, EURJPY, GBPUSD, CADCHF, USDJPY, NZDCHF, USDPKR, USDINR, BTCUSD, XAUUSD
- Prediction horizons: 1m, 2m, 3m, 5m, 15m
- Central circle displays only BUY or SELL and probability
- Only probability >= 60% is surfaced as a signal
- Latest 11 qualifying signals are displayed
- Current unresolved signal remains PENDING until expiry
- Last 10 resolved results produce the displayed win rate

## OTC micro-horizon strategies (new)

`lib/otcMicroStrategies.js` adds the missing sub-minute and short horizons
(10s, 15s, 30s, 1m, 2m, 5m) for Quotex OTC feeds:

| Horizon | Strategy | Logic | Skip when |
|---|---|---|---|
| 10s | WICK_FADE | Fade a wick that prints >=55% of the candle range against the close | chop |
| 15s | STREAK_FADE | Fade 4-candle same-color streaks (OTC mean reversion) | chop or breakout acceptance |
| 30s | MICRO_PULLBACK | Continue an EMA5>8>20 stack on a pullback rejection | chop |
| 1m | REJECTION_CONTINUATION | EMA trend sign + body/wick pressure | chop or repeated opposite zone |
| 2m | TREND_PULLBACK | EMA20/50 trend, gated until price rejects a pullback to EMA20 | no pullback / chop |
| 5m | SWEEP_RECLAIM | Fade a sweep of the 45-candle extreme that closes back inside | no sweep / mid-range / chop |

Usage:

```js
import { analyzeOtcMicro } from './lib/otcMicroStrategies.js';
const decisions = analyzeOtcMicro(m1Candles); // { 10: {...}, 15: {...}, ..., 300: {...} }
```

Each decision carries `direction`, `confidence`, `qualified`, the `tags` that
produced it, and `filters` (chop/gated/swept) so the UI can show why a signal
was skipped. Tests: `node --test test/otcMicroStrategies.test.js`.

**Honest limitation:** OTC candles are generated by the broker's server, not a
real market. These strategies are conditional-reversion / conditional-
continuation rules with explicit invalidation — they exploit microstructure
behavior only, and no module in this repo can predict a synthetic feed. Always
forward-validate on the demo account (your `audit/` pipeline exists for this)
before any live sizing.

## Current stage
The dashboard and server shell are implemented. No fake market predictions are generated. The next stage is live market-data ingestion and the server-side horizon-specific analysis engine.

## Run
```bash
npm install
npm start
```

Railway can deploy this repository as a Node service. It uses `PORT` automatically.

## Security
Market-data API keys must be stored as Railway environment variables and must never be shipped in browser JavaScript.
